## Production acceptance (2026-10-11)

A real deploy on Dockhold, from this repository at `3456bed`, with the
Deploy flow a reader uses: 1 GB app size, a secret bound as
`ADMIN_PASSWORD` from an entry named `hermes-agent-admin-password`.

| Step | Result |
| --- | --- |
| First start with App storage off | Refused. The app's log shows exactly "This app keeps its data on App storage. Turn on App storage in the Size tab; the app restarts on its own." The status names a crash and points to the logs. |
| App storage turned on, 10 GB | The app restarted on its own; `/health` 200. |
| Admin API | 401 with no session and after a wrong password, 200 after signing in with the secret. The Hermes dashboard is served behind the same login. |
| Public address | Hermes logged `public_url=https://<the app's own address>` with nothing typed. |
| Provider and channel | OpenRouter key, a free model and a Telegram bot token saved from the admin API, the same call the setup page makes. The gateway started and connected to Telegram in polling mode. |
| Pairing | A new Telegram user got a pairing code and no answer. Approve in the admin panel, no restart. The next message got an answer from the agent. |
| Redeploy | The app was stopped and started again. Afterwards the provider, the model, the Telegram token and the approved user were all still there, and the gateway reconnected on its own. |

The first free model tried was rate-limited by its provider (HTTP 429);
switching the model in the admin panel fixed it with no redeploy. That is a
property of free models, not of this app.

Not measured: memory under a real conversation, and the dashboard's browser
Chat tab.
